# ケータイショップへようこそ

ブラウザで遊べる **3D 放置観察シミュレーション**。
携帯ショップという小さな社会を、斜め上から眺めて楽しむゲームです。

プレイヤーはほとんど操作しません。
客が来て、受付をして、順番を待って、店員が接客して、トラブルが起き、
客が怒り、店員のストレスが溜まり、店内が少しずつカオスになっていきます。

> 「今回は何が原因で崩壊するんだ？」

## 遊びかた

| 操作 | 内容 |
| --- | --- |
| 1本指ドラッグ / マウスドラッグ | カメラ回転 |
| ピンチ / ホイール | ズーム |
| キャラをタップ | 店員・客の詳細パネル |
| ⏸ ×1 ×2 ×4 | 一時停止・進行速度 |
| 📣 応援 | 一定時間だけ店員が1名増える |
| 🧑‍💼 店長介入 | 一定時間、店員のストレス上昇を抑え、クレーム対応が倍速になる |
| 🚧 受付制限 | 新規の来店を一時的に止める。混雑は緩むが、売上機会を失う |

介入はこの3つだけです。増やしすぎず「使うタイミングを考える」ためのものなので、
どれもクールタイムがあります。

**平穏度が 0 になると「店舗崩壊」でゲーム終了**。
営業時間・来店客数・売上・最大待ち時間などの結果に加えて、
**その回の崩壊がどんな連鎖で起きたか**が経路として表示され、
最後に短いタイトルが自動生成されます。

ベスト営業時間 / 最高売上 / 最大対応人数 / 最多クレーム数は
`localStorage` に保存されます。

## 崩壊の連鎖

このゲームのトラブルは単発では終わりません。
各パラメータがお互いを悪化させるように繋がっています。

```
新人が難案件を担当 → 接客が長期化 → 待ち人数が増える
   → 待っている客の怒りが上がる → クレーム発生
   → ベテランがクレーム対応に取られる → 残った新人がまた難案件を担当
   → ミス発生 → 店員ストレス上昇 → 接客速度低下 → さらに待ち時間増加
```

崩壊の入口は毎回違います。

- 難案件と担当店員の**力量ミスマッチ**
- 一件の**クレーム**がベテランを拘束する(空きがなければ接客中の店員を引き剥がす)
- **特殊イベント**が混雑中に直撃する
- **売上至上主義**の店員が混雑中も提案を続けて接客が延びる
- 店員の**離席・メンタル崩壊・帰宅**による人手不足

### 危険な兆候

突然ゲームオーバーになるのではなく、見て分かる兆候が先に出ます。

- 客の頭上アイコンが `⌛ → 😓 → 😡 → 💢 → 🤬` と変化する
- 怒っている客の足元に赤いリングが出る
- ストレスの高い店員は姿勢が落ち、歩き方が重くなる
- HUD 上部に「待ち◯人」「限界寸前の店員◯人」などの兆候が並ぶ
- 平穏度が下がると照明・空の色・画面の縁・BGM が少しずつ不穏になる

### 店員のストレス段階

| 段階 | 起きること |
| --- | --- |
| 低 | 通常 |
| 中 | 接客速度低下・セリフが疲れる・ミス率微増 |
| 高 | 接客速度が大きく低下・満足度低下・ミス率上昇・無言になる/バックヤードを見る |
| 限界 | 一時的に接客不能・バックヤードへ逃げる・客と衝突・新しい客を取らなくなる |

耐性と壊れ方は店員タイプごとに違います。
新人はパニックを起こしやすく、短気は客と衝突しやすく、
ベテランは粘りますが一度限界を迎えると影響が大きい、という具合です。

### 客同士の影響

客は独立していません。店内の空気に影響されます。

- 近くの客が怒鳴る / クレームが起きる → 周囲の客の不満が上がる
- 長い列を見て入店する → 来店直後から忍耐度が低い
- 他の客が怒って帰る → 「そんなに待つの？」と不満が増える
- 楽しそうに帰る客を見る → 待たされている客の一部が苛立つ
- 逆に、空いているとき / スムーズに捌けているときは怒りが溜まりにくい

## 動作環境

- iPhone Safari / iPad Safari / Android Chrome / PC ブラウザ
- WebGL と ES Modules に対応したブラウザ
- サーバー処理は不要。静的ファイルのみで動きます

## 公開方法(GitHub Pages)

リポジトリの **Settings → Pages** で
`Deploy from a branch` を選び、対象ブランチのルート (`/`) を指定するだけです。
ビルド作業はありません。

ローカルで確認する場合は、ES Modules のため file:// ではなく HTTP で開いてください。

```sh
python3 -m http.server 8000
# → http://localhost:8000/
```

## 構成

```
index.html          エントリ / HUD の DOM
css/style.css       UI(スマホ縦画面優先・safe-area 対応)
js/main.js          描画・カメラ操作・メインループ
js/sim.js           シミュレーション本体(店員・客・接客・平穏度)
js/character.js     ローポリ人型モデルとアニメーション
js/shop.js          店舗レイアウトと 3D 構築
js/nav.js           グリッド A* による経路探索
js/cascade.js       崩壊連鎖の因果グラフと結果タイトルの生成
js/data.js          名前・案件・性格・トラブル・特殊イベント・セリフ
js/config.js        バランス調整用の定数
js/ui.js            HUD / ログ / 詳細パネル / 結果画面
js/audio.js         手続き的 BGM・効果音(音声ファイル不要)
vendor/             three.js (r160, MIT)
```

## 設計メモ

- 3D はすべて Three.js のプリミティブ形状の組み合わせ。外部モデル・テクスチャ画像は不使用
- 影は円形の擬似シャドウ、ポストプロセスなし、マテリアルは `MeshLambertMaterial` を共有
- キャラクターは最大 40 体。遠くの人物はアニメーション更新を 1/3 に間引き
- ロジックは固定タイムステップ、見た目は可変タイムステップで更新
- BGM は WebAudio によるリアルタイム生成。平穏度が下がるほどテンポが上がり不協和になる
- 崩壊連鎖は「原因つきイベント」の有向グラフ。終了時に平穏度ダメージを子から親へ
  減衰させながら遡上させ、一番責任の重い根を主因として取り出す (`js/cascade.js`)
- 客同士の影響は毎フレームの総当たりを避け、店内の空気は 0.5 秒ごとのスカラー、
  怒鳴り声などの伝播は発生時に一度だけ O(n) で処理する
- 怒りリングはジオメトリ・マテリアルを全員で共有し、脈動はスケールのみで表現する
